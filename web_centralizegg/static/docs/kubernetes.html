<div class="doc-content"> <h3><i class="fa-solid fa-dharmachakra"></i> Kubernetes Cluster Monitoring</h3> <div class="doc-section"> <h4>🚀 Cómo Iniciar</h4> <ol> <li>Accede a <strong>Contenedores > Kubernetes</strong>.</li> <li>En la sección de <strong>Configuración</strong>, añade un nuevo servidor.</li> <li>Sube tu archivo <code>kubeconfig</code> o pega el contenido en el campo correspondiente.</li> <li>Centralizegg conectará con el API server y comenzará a recolectar métricas del cluster.</li> </ol> </div> <div class="doc-section"> <h4>📋 Requerimientos Mínimos</h4> <ul> <li><strong>Acceso API:</strong> El backend debe tener conectividad con el API Server de Kubernetes.</li> <li><strong>Kubeconfig:</strong> Un archivo de configuración válido con permisos de lectura para nodos, pods y servicios.</li> <li><strong>Metrics Server:</strong> Recomendado tener <code>metrics-server</code> instalado en el cluster para métricas de recursos en tiempo real.</li> <li><strong>Permisos (RBAC):</strong> ServiceAccount o usuario con permisos de <code>get</code>, <code>list</code> y <code>watch</code> en el núcleo de la API.</li> </ul> </div> <div class="doc-section"> <h4>✨ Características Principales</h4> <ul> <li><strong>Estado de Nodos:</strong> Visualización detallada de CPU, memoria y presión de disco por cada nodo del cluster.</li> <li><strong>Historial Profundo por Nodo:</strong> Gráficos históricos de CPU, Memoria, Red y Disco para cada nodo individual mediante el selector de nodos en la herramienta de Historial Global.</li> <li><strong>Monitoreo de Pods:</strong> Listado de pods con estado (Running, Pending, Failed), reinicios y uso de recursos.</li> <li><strong>Salud de Servicios:</strong> Verificación de endpoints de servicios y balanceadores de carga. </li> <li><strong>Visualización de Eventos:</strong> Historial de eventos del cluster para depurar problemas de despliegue o fallos de nodos.</li> <li><strong>Logs del Host en Tiempo Real:</strong> Terminal integrada en Historial Global para visualizar logs del sistema (<code>journalctl</code>) vía SSH desde cada nodo.</li> <li><strong>Seguridad Integrada:</strong> Gestión segura de credenciales <code>kubeconfig</code> almacenadas de forma cifrada en la base de datos.</li> </ul> </div> </div>
