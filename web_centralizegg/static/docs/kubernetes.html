Kubernetes Cluster Monitoring

🚀 Cómo Iniciar

  1. Accede a Contenedores > Kubernetes.
  2. En la sección de Configuración, añade un nuevo servidor.
  3. Sube tu archivo kubeconfig o pega el contenido en el campo correspondiente.
  4. Centralizegg conectará con el API server y comenzará a recolectar métricas del cluster.

📋 Requerimientos Mínimos

  • Acceso API: El backend debe tener conectividad con el API Server de Kubernetes.
  • Kubeconfig: Un archivo de configuración válido con permisos de lectura para nodos, pods y servicios.
  • Metrics Server: Recomendado tener metrics-server instalado en el cluster para métricas de recursos en tiempo real.
  • Permisos (RBAC): ServiceAccount o usuario con permisos de get, list y watch en el núcleo de la API.

✨ Características Principales

  • Estado de Nodos: Visualización detallada de CPU, memoria y presión de disco por cada nodo del cluster.
  • Historial Profundo por Nodo: Gráficos históricos de CPU, Memoria, Red y Disco para cada nodo individual mediante el selector de nodos en la herramienta de Historial Global.
  • Monitoreo de Pods: Listado de pods con estado (Running, Pending, Failed), reinicios y uso de recursos.
  • Salud de Servicios: Verificación de endpoints de servicios y balanceadores de carga.
  • Visualización de Eventos: Historial de eventos del cluster para depurar problemas de despliegue o fallos de nodos.
  • Logs del Host en Tiempo Real: Terminal integrada en Historial Global para visualizar logs del sistema (journalctl) vía SSH desde cada nodo.
  • Seguridad Integrada: Gestión segura de credenciales kubeconfig almacenadas de forma cifrada en la base de datos.
